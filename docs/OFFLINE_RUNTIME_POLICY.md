# 完全オフライン実行仕様（必須・2026年11月12日）

## ユーザーの必須条件

**Windows 11アプリ実行時の送受信はゼロにする。** Google・Microsoft・PaddlePaddle・GitHub・開発者サーバー・LAN・localhostを含め、外部／内部のネットワークへアクセスしない。通信を許可するOCRモードも設けない。

- 画面画像、選択範囲、画像内の文章、OCR結果、クリップボード、音声、操作履歴、障害情報、設定をネットワークへ送信しない。
- OCRはWindows標準のローカルOCR、または**必要モデルをアプリと一緒に配布したPaddleOCR/ONNX**を使用する。クラウドOCR／Google Cloud Visionを製品に組み込まない。
- 読み上げはインストール済みのオフライン日本語音声合成エンジンを使用する。
- 文字列の補正・日本語形態素解析・文脈処理などを追加する場合も全てローカル処理。オンラインのLLM・翻訳・辞書APIは禁止。
- ソフトの起動、Alt＋ドラッグ、日本語OCR、読み上げ、設定保存、再起動、モデル初期化、エラー表示・診断ログの全てを、ネットワーク接続なしで完結させる。
- 初回起動時のモデル取得・ライセンス照会・更新確認・テレメトリー・エラー報告・ユーザー認証は禁止。
- 必要なOCR日本語モデルは配布物に同梱する。ファイル不足時は通信せずに明示的なエラーとして扱い、従来のローカルOCRへ戻す。利用者がGoogleやクラウドの認証情報を設定する必要はない。
- 現行Windows OCR・SAPI音声がOSにインストールされている必要がある場合は、配布物・起動前チェック・使用説明で明記する。アプリが裏でWindowsの言語パックを取得してはいけない。

## 開発中のインターネット利用との区別

- **GitHub Actions、NuGet、OCRモデルの公式リポジトリからの取得は、開発者側のビルド・検証工程に限定**する。ここで取得した依存関係やモデルは、必要なライセンスを同梱してユーザー配布ファイルに収める。
- ユーザーが使うWindows EXEと同梱DLL／モデルにはネットワーク取得コードを持たせない。モデルがあるからといってアップデートチェックや自動ダウンロードを追加しない。
- GitHub上の実験用Pythonテストがモデルをダウンロードする場合があっても、それを実行アプリや配布物に含めない。

## 検証・品質ゲート

1. `scripts/Verify-OfflineRuntime.ps1` で製品C#／PowerShell／プロジェクト定義にネットワークAPI、URL、通信SDKがないことをCIチェック。失敗したらビルド・Releaseを停止する。
2. 新しいNuGetやネイティブDLL、OCRモデルを採用するときは、転送・テレメトリー・更新チェック機能がないことを依存関係まで確認する。
3. Windows 11で**ネットワークアダプターをオフにした状態**から起動して、Alt＋ドラッグ、日本語OCR、日本語読み上げ、3画面拡大、設定保存・再起動を実機確認する。
4. Windowsファイアウォール／プロセス別通信監視で、アプリの通信試行がないことを実測する。特に初回起動とエラー時、OCRモデル未配置時を確認する。
5. OCR精度・所要時間・デグレを日本語画像で比較し、旧ローカル方式の動作を維持する。
6. 静的解析やCIビルド成功だけで、実機のネットワーク通信ゼロを実測済みと報告しない。

## 2026年11月12日の現状

- メインアプリ `src/ScreenReaderAssist/` はWindows標準OCRとローカル音声を使用。**Google Cloud VisionのネットワークOCR実装はありません**。
- `experiments/ocr/` にPaddleOCR比較用の試験コードがありますが、メインEXEには組み込まれていません。
- そのため、Google Cloud Visionの追加案は**撤回**し、今後実装しません。
- GitHub Actionsの静的監査は追加。実機の完全オフライン実行・送受信パケット検証は別途必要です。

**セキュリティ上の注意：** アプリ自身が通信しなくても、Windowsや他のアプリ、ユーザーのゲームが通信している可能性はあります。この仕様は本製品のプロセスと同梱コンポーネントのネットワーク動作に適用します。
