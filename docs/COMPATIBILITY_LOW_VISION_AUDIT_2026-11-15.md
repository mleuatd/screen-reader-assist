# Windows 11 競合・視認性・処理速度の事前監査（2026-11-15）

## 変更した仕様
- 他アプリのAlt+左クリック操作を奪わないよう、拡大鏡の「Alt＋左も使用（競合注意）」を初期OFF。既存の設定ファイルにキーが無ければOFF。必要なときだけ利用者がONにできる。Alt＋右ドラッグによるOCRは従来どおり。OCRフック自体も既存のチェックボックスでOFFにできる。
- Ctrl、Windowsキーとの複合操作、通常クリック、無関係のマウスメッセージはOCR操作とみなさないことをWindows PowerShell検証で確認。
- 選択枠の35msタイマーは常時起動をやめ、実際のドラッグ中だけ動かし、ボタンを離したとき・取消時に停止。待機中の不要な周期処理を減らす。CPU利用率は未実測。
- 拡大鏡ツールバーと大型操作画面、および読み上げ設定画面のボタンは太字Meiryoで表示。押している間は黄色背景＋黒文字、キーボードフォーカスには太い黄色枠を表示する。線を人工的に太らせすぎて漢字が潰れないようアウトライン加工はしない。

## 想定アプリ競合と残る実機確認
- Edge／Chrome／Firefox：Alt+左の戻る操作、Alt+右の進む操作、コンテキストメニュー。**Alt+右OCRは有効時に競合する場合がある**。必要時に全体OCRをOFF。
- Excel／Visual Studio／エクスプローラー：Altメニュー、右ドラッグ移動・コピー、範囲選択。
- Windows拡大鏡・ナレーター・NVDA・JAWS：音声二重読み、Ctrl+Alt+Rなどのホットキー登録競合、UIAの誤読。ホットキー競合はログに警告を残し、相手のアプリから強制的に奪わない。
- PowerToysのマウス機能、ジェスチャーツール、リモートデスクトップ、ペンタブレット：グローバルマウスフックの共存と入力注入。
- 3画面、DPIの異なる画面、タッチ・非タッチ混在、モニターの抜き差し、画面の負座標、Windows Snap、UAC、ゲームの排他フルスクリーン。
- Escによる選択取消、30秒のタイムアウト、ドラッグ中に別画面へ移動、連打、音声再生中の停止、スリープからの復帰。

## テスト可能範囲と速度
GitHub ActionsでC#コンパイル、ドラッグ計算、Alt修飾キー判定、OCRサンプル認識、オフライン実行、ボタン表示のコード上の契約、ZIP作成を検査する。3画面実際の入力、他社ソフト同時実行、視認性の実測と日本語発声までの実時間はGitHubランナーでは確認できない。

拡大画面追従の40msポーリングは維持する。短縮してCPU負荷・操作干渉を増やさないため。Alt＋右OCRはPNG保存＋PowerShell 5.1起動＋Windows日本語OCR＋音声合成の別経路なので、本体C#の高精度OCR速度と同一視しない。実機では `%LOCALAPPDATA%\\日本語拡大鏡\\ocr-performance.log` の工程別ミリ秒を参照し、必要に応じ次の改善を検討する。
