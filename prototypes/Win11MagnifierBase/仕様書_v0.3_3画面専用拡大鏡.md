# Windows 11 拡大鏡ベース 仕様書 v0.3

## 1. 目的

既存の Windows 11 標準拡大鏡を利用する v0.1 は維持しつつ、作業用2画面＋拡大表示専用1画面という「3画面運用」に対応した独立ビューアーを追加し、その拡大画像を左右ドラッグして倍率を変更する。

### 画面配置例

| モニター | 役割 | 表示内容 |
|---|---|---|
| モニター1 | 作業用 | エクスプローラー、ブラウザー等。通常倍率のまま操作する。 |
| モニター2 | 作業用 | 開発、Excel等。通常倍率のまま操作する。 |
| モニター3 | 閲覧専用 | マウスがある作業画面（1・2）の部分拡大映像を表示する。 |

Windowsの設定は「表示画面を拡張する」。**モニター番号はWindowsの認識順と実際の左右配置が異なる場合があるので、UIから任意の表示先を選べるようにする。**

## 2. 画面3でのウィンドウ操作

1. 通常のタイトルバーのある独立ウィンドウを用意する。
2. 別モニターへドラッグした後、タイトルバーのダブルクリックで **そのウィンドウが存在するモニターの作業領域内**に最大化する（Windowsの一般的な最大化）。
3. プライマリディスプレイを要求しない。
4. 最大化中でもタイトルバー・拡大倍率・追従停止ボタンにはアクセスできる。
5. タスクバーの範囲は標準のWindows最大化と同じく占有しない。「枠なし全画面」とは区別する。

## 4. 実装の方針

- Windows PowerShell 5.1 がローカルの C# ソースを読み、Windowsの標準フレームワーク上で独立ビューアーを起動する。無料、追加パッケージ不要。
- Microsoft Magnification APIの **ウィンドウ型拡大鏡コントロール**を使用する。`MagInitialize`、`MagSetWindowTransform`、`MagSetWindowSource`、`MagUninitialize`。
- 子の拡大コントロールをレイヤードウィンドウでホストする。ビューアーのサイズに連動して子ウィンドウも更新する。
- 画面上のカーソル位置と、表示先となったウィンドウのモニターを比較。表示先上なら拡大元の座標を保持する。
- 25Hzの軽量な位置確認タイマーを使用し、拡大元の四角形が変化したときだけAPIで更新。背景映像の描画はWindows側で行う。
- **プレビュー画像上の左ドラッグに限り倍率を変更する。** 最初のクリック位置から水平48px進むごとに、倍率に0.10倍（=10％ポイント）を加減する。例：250%→260%→270%。1.10倍を掛け続ける方式ではない。
- 47px以内の微小な移動は無視。右ドラッグで拡大、左ドラッグで縮小。反対方向へ戻せば元倍率へ戻る。倍率の下限は100%、上限は1600%。
- プレビューはネイティブのMagnifier子ウィンドウなので、その子ウィンドウだけに WinForms `NativeWindow` のメッセージ処理を割り当てる。パネルの通常イベントには依存しない。
- ドラッグ中のみ自分自身のウィンドウでマウスキャプチャ。マウスボタンを離す、キャプチャが解除される、ウィンドウが閉じられると解放する。Windows全体のフック、`SendInput`、OSのポインタ座標変更は行わない。
- ドラッグ中は設定ファイルを書かず、終了時に変更分を1回保存する。「左右ドラッグ有効」チェックは設定に保存する。
- **プレビュー画像上のクリックで元画面は操作しない。** 1・2枚目の本来のクリック、ドラッグ、キーボード入力を壊さないことを優先する。
- 最前面固定はしない。管理者権限不要。入力フック不要。専用ドライバー不要。
- 起動前のWindows DPI設定が既に確定している場合もあるため、DPI認識要求が受け付けられない環境での挙動は要実機検証。

## 5. 注意点・未解決事項

- 実機のWindows 11での描画確認・耐久確認は実施していない。
- Windows Magnification APIは、保護された映像や一部の描画方式で表示できない場合がある。
- Microsoftの古いサンプルはマルチモニター非対応と明記している。**本件の独自ビューアーが3画面で正常描画できることを保証するものではない。** 本件は公式APIを用いた独自実装であり、接続構成別テストが必要。
- Windows 11 の標準拡大鏡には画面ごとの独立ズーム機能があるが、**別モニターに元画面を集約する閲覧用プレビュー**とは異なる。
- アプリ内部の座標系は混在DPIモニターで注意が必要。100/150/200%など組み合わせ別の表示位置の検証を優先する。

## 6. ドラッグでの倍率変更（v0.3）

1. モニター3に最大化した拡大映像にマウスを重ねる。カーソルの形を左右方向に変える。
2. 左ボタンを押したまま右へ48px移動するたび倍率を＋0.10倍（10％ポイント）する。左へ48px移動するたび－0.10倍する。
3. 押下位置から47px以内の左右移動は拡大倍率を変えない。上下移動だけでは変えない。
4. 例：2.50倍→右96pxで2.70倍→左へ96px戻すと2.50倍。
5. ドラッグを終了してもその倍率を保持し、次回起動時も復元する。頻繁なディスク書き込みを避ける。
6. 「左右ドラッグ有効」のチェックを外すと画像上のドラッグは無効になる。画像のクリックによる別アプリへの入力送信は行わない。
7. タッチ操作はWindowsがマウス互換イベントを発生させる環境で動作する可能性があるが、専用のタッチ入力処理は未実装。**タッチ対応の保証はしない。**

## 7. 安定性の受け入れテスト

1. 3台を「拡張」にし、すべて100%表示倍率で起動。3番目にビューアーを配置し最大化。
2. マウスを1→2→1へ移動。3番目の拡大対象が追従し、1・2番目のマウス操作やクリック位置が変わらないこと。
3. マウスを3へ移動して操作ボタンを押す。3番目が自分自身を再帰表示せず、最後の拡大位置が保持されること。
4. 3番目のタイトルバーをダブルクリックして復元／最大化を10回繰り返す。表示崩れ・ブラックアウトが発生しないこと。
5. 3番目のウィンドウを別モニターにドラッグし、そこで最大化できること。
6. 画面ごとに100%、150%、200%の異なる表示倍率を設定して追従範囲を検証する。
7. ビューアーを最小化・復元。閉じた際に通常のカーソルと1・2の画面が正しく残ること。
8. 画面3を外して復帰させる。表示先が見失われず、プライマリ画面に復帰できること。
9. ブラウザー、Excel、エクスプローラー、開発環境を長時間動作させ、過剰なCPU/GPU負荷や入力遅延が発生しないこと。
10. Windows標準拡大鏡との同時利用は避けて試験し、異常時の回復方法を記録する。
11. 拡大画像上を右48px、左48px、右96px、左96px、反転、47px未満、縦方向へ動かす試験をする。
12. ドラッグ途中で画面端を越える、Alt+Tabなどでフォーカスを失う、終了する場合に押しっぱなし状態が残らないことを確認する。
13. タッチを試す場合は指の押下・移動が互換マウスメッセージになるか確認し、ならない端末は未対応として扱う。

## 8. 今後の改善候補

- マウス中心追従のほか、キーボードフォーカス・文字入力キャレット追従（UI Automation等）。
- 左右に画面1・2がある場合の追従範囲、滑らかなアニメーションと遅延の設定。
- 高コントラスト、色反転、カーソル強調の独立設定。
- OCR・読み上げ・テキスト選択ツールを別モジュールで追加。
- 実機でAPI方式が不安定なら Windows Graphics Captureなど別方式へ切り替える。安定性優先で採用を決める。
